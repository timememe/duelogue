# Danganronpa V3: Killing Harmony — визуально-нарративный движок (справочник)

**Назначение:** сборник того, из чего состоит презентационный слой Danganronpa V3 (Spike
Chunsoft) — режиссура реплик, разделение экрана на манга-подобные панели, минигеймы как
партитуры сцен. Собрано из открытых источников (см. §5), автор не играл в игру — это
вторичный разбор для проектирования «ядра режиссёра» DUELOGUE, **не привязан к текущей
архитектуре проекта** (см. по аналогии [ace_attorney_animation_states.md](ace_attorney_animation_states.md)).

---

## 1. Базовый ADV-слой: камера как внимание, не как переключатель

V3 меняет модель относительно ранних игр серии: вместо fade-in/fade-out отдельного спикера,
**диалоговый бокс «зумится» на текущего говорящего и подъезжает к нему, как поворачивалась бы
голова слушателя**. Остальные персонажи не исчезают — они остаются видны на периферии/фоне.
Эффект — «населённая комната», а не изолированный портрет крупным планом.

Важное для V3: протагонист (Каэдэ, затем Сюичи) сам физически присутствует в кадре и реагирует
на чужие реплики — не невидимый рассказчик, а участник, за которым тоже наблюдают.

**Цветовое кодирование текста** — устойчивый код, а не разовая раскраска:
- белый текст = произнесено вслух;
- синий текст = внутренний монолог;
- в дебатах отдельно: синий = верная дедукция, розовый = неверная.

**UI как диегетический носитель состояния**, не нейтральная рамка: заголовок «CLASS TRIAL»
вращается позади персонажей (не висит статичной плашкой); при смене POV-персонажа (казнь
Каэдэ → повествование от Сюичи) **сам интерфейс гаснет и перезагружается** — механический
UI-бит несёт эмоциональный вес наравне с текстом.

V3-рестайлинг UI поверх этого: портреты обрезаны до половины лица, угловые «осколочные» линии
разной прозрачности, таблички с именами — под углом. Визуальная плотность интерфейса намеренно
растёт вместе с нарративной сложностью/хаосом сцены.

## 2. Минигеймы как партитуры режиссуры (паттерн сцены, не инпут-механика)

Каждый минигейм ниже описан не как способ ввода (кнопки/QTE), а как **форма сцены** —
сколько голосов звучит одновременно, как делится экран, какой ритм чтения. Это то, что
переносимо в DUELOGUE; конкретный инпут (стрельба, слэш, ритм-кнопки) — нет.

| Минигейм | Форма сцены |
|---|---|
| **Non-Stop Debate** | Один голос за раз, поток реплик-«снарядов» плывёт по экрану; слабые места подсвечены (жёлтый/оранжевый); камера держит общий план говорящей группы. Базовый ритм — «один активный спикер + видимый фон». |
| **Mass Panic Debate** (только V3) | Три персонажа говорят ОДНОВРЕМЕННО — экран буквально делится на параллельные дорожки/панели, поверх — текст-«шум», мешающий читать. Хаос — это и есть содержание: визуализирует групповой нервный срыв, а не просто усложняет инпут. |
| **Debate Scrum** | При равном расколе голосов состав физически выстраивается в две шеренги по разные стороны — блокировка тел ЕСТЬ визуализация раскола мнений. Быстрый обмен репликами-«ключами» с двух сторон, разрешение — единый синхронный «Full Drive». |
| **Rebuttal Showdown / Blade Lock** | Формат дуэли 1×1: чужой довод рендерится как физический разрубаемый объект на 2D-плоскости; кульминация — удержанный силовой клинч (Blade Lock) перед финальным ударом по «золотому» доводу. Грамматика единой цели с нарастающей ставкой. |
| **Argument Armament** | Сборка реплики-контрудара из готовых словесных блоков под ритм, синхронно с «раздеванием» защит паникующего персонажа — механика визуализирует сборку ответа из дискретных частей во времени. |
| **Closing Argument** | Финал каждого суда: игрок собирает **комикс-раскадровку** из «панелей-истины» (среди которых есть ложные — их нужно опознать и отбросить), восстанавливая хронологию дела. По завершении раскадровка проигрывается как **аниматик** — панели оживают, камера идёт по ним и между ними, поверх — закадровый текст протагониста. Это буквально **«чтение анимированной манги»** в готовом виде — прямой референс на формулировку задачи. |

## 3. Грамматика манги (Scott McCloud) — теория монтажа событий в панели

McCloud выделяет **шесть типов перехода между панелями**: moment-to-moment (мельчайшее
приращение одного действия), action-to-action (субъект проходит через отдельные действия),
subject-to-subject (смена субъекта внутри сцены), scene-to-scene (скачок во времени/месте),
aspect-to-aspect (разные грани ОДНОГО момента, показанные параллельно) и non-sequitur (связи
нет).

Ключевое наблюдение из теории: **западный комикс тяготеет к action-to-action, японская манга —
к moment-to-moment и aspect-to-aspect** (собрать один момент из разрозненных осколков даёт
кинематографичную плотность вместо последовательного повествования). Между любыми двумя
панелями работает «closure» — читатель сам достраивает пропущенное; выбор, что показать явной
панелью, а что оставить в «водостоке» (gutter) — это рычаг темпа и плотности.

Это прямо релевантно DUELOGUE: каскады клинча уже устроены «взрывами», а не ровной лентой
(см. память [[duelogue-combo-grammar]]) — по ритму это ближе к moment-to-moment/aspect-to-aspect
манге, чем к западной раскадровке. Решение «сколько панелей показать явно, а что сжать» —
это и есть работа режиссёра, а не декорация поверх готовой сцены.

## 4. Смежный референс: диегетический UI Persona 5

Коротко, для контекста (не Danganronpa, но тот же жанровый регистр): интерфейс Persona 5
выстроен как манга-объект внутри мира, а не нейтральный HUD поверх экрана — иконки настроения
персонажей, типографика-«шёпот» толпы, цветовой контракт red/white/black держит всю
композицию. Урок, переносимый и на V3-рамки, и на DUELOGUE: **рамка/чрома панели сама может
играть настроение**, не только фон внутри неё (в DUELOGUE к этому уже есть шаг — mood-профиль
спидлайн-фона в `reaction_scene.gd`, см. §6 ниже).

## 6. Мостик к DUELOGUE (для следующего разговора, не спека)

Держатели контракта уже существуют и явно указывают на этот же шов:

- `duelogue/core/characters/reaction_scene.gd` — уже «AA-уровень»: один портрет + бабл на
  весь экран, строго последовательно (`_gen` глушит предыдущую сцену при новом вызове).
  Потолок текущей архитектуры — ровно здесь: одна панель за раз.
- `context/narrative_engine.md` §16 — контракт «Стейт = функция(акт × регистр × зал × исход)»
  уже разделяет ВЫЧИСЛЕНИЕ семантики (движок/контроллер) от РЕНДЕРА (скин=данные). Режиссёр
  композиции — естественно третий слой между ними: не что показать, а **как разбить на панели**.
  Тот же файл уже держит незакрытую парковку: «брейкдаун на `match_ended`» — по форме это
  готовый слот под Closing-Argument-style мангу-рекап, и материал для него (mood/state на
  каждую реплику, стенограмма) по контракту §16 уже пишется.
- Каскады клинча (`combo_register.gd`, [[duelogue-combo-grammar]]) — естественный кандидат на
  Mass-Panic-Debate-паттерн: сейчас 2-3-ударная серия рендерится как очередь одиночных
  full-screen сцен; манга-грамматика §3 подсказывает разбивку на несколько одновременных
  панелей одного «биения» вместо последовательной ленты.

Дальше — вопрос направления, не разбора: с какого среза начинать (2-панельная «спикер +
периферия» как наименьший шаг, или сразу многопанельный ралли-бит), обсуждается отдельно.
